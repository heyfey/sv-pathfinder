## Prerequisites

| To use… | You need | One-time setup |
|---|---|---|
| The extension | VS Code **1.93.0+** | Install from the [Marketplace](https://marketplace.visualstudio.com/items?itemName=heyfey.sv-pathfinder) |
| **Design navigation** (required) | **One design input** — a **`.f`** filelist (backend: **slang-server** *(default)* or **Surelog**) *or* a **`.uhdm`** database (native reader, **Linux x64**; no backend needed) | [Open a design](#open-a-design) |
| **Schematic viewer** | Nothing to install: the schematic runtime is downloaded once on first use (Linux x64, macOS, Windows x64) | [Schematic viewer](#schematic-viewer) |
| **Waveform** value annotation & "Show in Waveform" | The [Vaporview](https://marketplace.visualstudio.com/items?itemName=lramseyer.vaporview) extension | [Waveform integration](#waveform-integration) |

> **Platform:** primarily developed and tested on **Linux x64** (Ubuntu 22.04, AlmaLinux 8). Only the
> `.uhdm` database reader strictly requires Linux x64; the slang-server backend, schematic, and
> waveform features are not Linux-specific.

## Open a design

sv-pathfinder navigates two kinds of design database:

- **`.f` filelist** — parsed and elaborated on the fly. Pick the backend via `sv-pathfinder.compiler`:
  - **`slang-server`** *(default)* — based on the [slang](https://github.com/MikePopoloski/slang)
    library. **Install the
    [slang-server VS Code extension](https://marketplace.visualstudio.com/items?itemName=Hudson-River-Trading.vscode-slang)**
    and configure it.
  - **`Surelog`** — elaborates the `.f` with [Surelog](https://github.com/chipsalliance/Surelog)
    (install it, or set `sv-pathfinder.surelogPath`).
- **`.uhdm` [UHDM](https://github.com/chipsalliance/UHDM) database** — a pre-elaborated database **generated by [Surelog](https://github.com/chipsalliance/Surelog)**
  ([how](#generating-a-uhdm-database-with-surelog)). Opened directly by the native UHDM reader, which
  requires **Linux x64**; the `sv-pathfinder.compiler` setting does not apply.

Then open the **sv-pathfinder** activity-bar view → **Open Design** (or run **sv-pathfinder: Open
Design**) and pick a **`.f`** or **`.uhdm`**.

### Generating a UHDM database with Surelog

```bash
# produces ./slpp_all/surelog.uhdm
surelog dut.v tb.sv -elabuhdm -parse -sverilog -d uhdm
```

Built against UHDM v1.87 — use Surelog v1.87 for compatibility. See
[BUILD_SURELOG.md](BUILD_SURELOG.md).

## Waveform integration

Simply install the [Vaporview](https://marketplace.visualstudio.com/items?itemName=lramseyer.vaporview)
waveform viewer. With a waveform open, sv-pathfinder then:

- annotates both the **source editor** and **schematic wires** with signal values at the marker time, and
- lets you **add signals into the waveform** (right-click a signal/scope → **Show in Waveform**).

## Settings

| Setting | Description |
|---|---|
| `sv-pathfinder.compiler` | `.f` backend: `slang-server` (default) or `Surelog`. |
| `sv-pathfinder.surelogPath` | Path to the Surelog executable (Surelog backend). |
| `sv-pathfinder.showModulesView` | Show the Modules view (reload window to apply). Default `true`. |
| `sv-pathfinder.valueAnnotationFormat` | Inline waveform-value format: hex / dec / bin. |
| `sv-pathfinder.sourcePathFrom` / `sourcePathTo` | Remap source paths across machines (both must be set). |
| `sv-pathfinder.schematicRuntimePath` | Folder of a hand-installed schematic runtime; empty = downloaded automatically. |
| `sv-pathfinder.schematic*` | Schematic appearance & elaboration — see [SCHEMATIC.md](SCHEMATIC.md). |

## Building from source

The `.uhdm` reader is a native Node addon linked against UHDM, which is pinned as the
`third_party/UHDM` git submodule (Linux x64 only). The reference build platform is AlmaLinux 8
with the GCC toolset, which is what CI uses and what keeps the shipped binary loadable on EL8/EL9:

```sh
sudo dnf install gcc-toolset-14 cmake make python3.11 python3.11-pip
sudo alternatives --set python3 /usr/bin/python3.11
python3 -m pip install --user orderedmultidict   # UHDM's code generator
scl enable gcc-toolset-14 bash                   # C++17 compiler on PATH for the steps below
```

Build UHDM once, then the usual `npm run compile`:

```sh
git submodule update --init --recursive   # UHDM + its capnproto dependency
npm install
npm run build-uhdm                         # cmake: Release, -fPIC, no tests (scripts/build-uhdm.sh)
npm run compile                            # node-gyp rebuild + type-check + lint + esbuild
```

`binding.gyp` reads the UHDM build from `third_party/UHDM/build`; set `UHDM_HOME=/path/to/uhdm/build`
to use another build (it must be compiled with `-DCMAKE_POSITION_INDEPENDENT_CODE=ON`).
